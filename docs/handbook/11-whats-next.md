## 为什么需要它

学完 MLP 会有两种典型情绪：一种是"我是不是已经学完了"，另一种是"后面还有一堆看不懂的东西，我完了"。这一章同时治这两种病，方法是给一张地图：

- 每样东西**在解决什么问题**（一句话）
- 它和你已经写过的 MLP 是什么关系（是替换、是补充、还是根本不在一个层面）
- 如果你对某类问题感兴趣，下一步该碰哪个

地图的用法是**知道有这个地方、知道它治什么病**，不是现在就开车过去。所以这章刻意写得很浅，故意不给你能直接上手的细节——那些留给后续的 Issue 和 D2L 的对应章节。

## 直觉

MLP 干的事非常朴素：把输入**拍平成一长条数字**，然后做加权求和。照片本来是二维的，它会先被剪成一条长纸条；一句话本来是有先后顺序的，它也被当成一堆并列的词。这一招在很多任务上居然够用，所以你才跑出了 0.88 的准确率。

但它有两个天生的毛病：

- **看照片时**：它只会盯着"第 173 个像素"这种绝对位置做事。你把照片整体右移一格，对它来说整条纸条全变了，之前学的东西一点都用不上。
- **读句子时**：它不理解"谁在前谁在后"。要让它记住顺序，它只能给每个位置单独记一套规矩，句子一长就记不过来了，更别提训练时没见过更长的句子。

后面那些模型，本质上都是在**把这个被拉直的世界还原回去**：

- **CNN** 像拿一个放大镜在照片上从左到右、从上到下扫，同一个放大镜扫遍整张图。它在乎的是"局部长什么样"，而不是"这个花纹出现在第几行第几列"。
- **RNN** 像读书，一个字一个字看，一边看一边在心里记着前面讲了什么，读完最后一个字时心里有个总结。
- **Attention / Transformer** 像开卷考试：桌上摊着一堆资料，你按题目去翻——哪一段和当前问题相关，就重点取哪一段。它不是按顺序读，是**按相关度取**。

一句话概括区别：MLP 是"把所有东西排成一队挨个看"；CNN 是"带着同一把尺子到处量"；RNN 是"边读边记"；Attention 是"按需索引"。

## 最小原理

> 这里只讲"为什么 MLP 不够"，不推导任何模型。公式只保留说明问题的那一个。

### 1. 图像：参数量平方增长 + 平移信息丢失

**参数量的问题。** 假设输入是 $H \times W \times C$ 的图像（比如 $32 \times 32 \times 3$），第一层隐含层有 $D$ 个单元，那么光这一层就有：

$$N_{\text{MLP}} = (H \cdot W \cdot C) \cdot D$$

长宽各翻一倍，参数量变成 **4 倍**；换成 $224 \times 224$ 的照片，这一层就上千万参数。而卷积层不一样，它的参数量只和"卷积核多大、有多少个通道"有关，**和图片分辨率无关**——同样一个"检测横线"的核，在大图小图上都能用。

**平移的问题。** 自然图像的规律是**局部**的、而且**到处都可能出现**："猫耳朵"这个花纹出现在左上角还是右下角，它都还是猫耳朵。MLP 对每个像素位置有独立的权重，所以它必须**在每个位置分别学会**这件事——这既浪费参数，也学不好。卷积用**权值共享**把这件事说清楚：同一个核在整张图上滑动，于是：

$$\text{如果你把输入平移一下，输出也只是被平移（而不是变成一个全新的结果）}$$

这叫**平移等变性**。局部连接 + 权值共享，是 CNN 相对 MLP 唯一真正的两个新东西，其余都是工程细节。

### 2. 序列：顺序是结构，而 MLP 没有结构可依赖

对一个长度为 $T$ 的序列，MLP 看到的只是 $T$ 个并列的输入。它没有"第 $t$ 个和 $t+1$ 个相邻"这个概念，所以要处理"同一个词出现在不同位置"，它得为每个位置学一套独立参数——**参数量随长度线性增长，而且换长度就报废**。

RNN 的做法是引入一个**隐藏状态**：每一步都用"上一步的记忆"和"这一步的输入"一起算出新的记忆：

$$h_t = f(h_{t-1}, x_t)$$

关键是 $f$ 在**所有时间步上是同一套参数**。于是参数量与序列长度无关，训练时见过 20 个词的句子，推理时可以试着处理 100 个词（效果另说，但结构上允许）。

代价也在这里：因为必须一步一步算，$h_t$ 依赖 $h_{t-1}$，**没法并行**；序列一长，早先的信息在链上被反复乘，容易衰减掉（长程依赖问题）。这两点，正是后面 Transformer 出现的直接原因。

### 3. Attention 为什么变成主流

Attention 的核心是**内容寻址**：不再"按位置逐个处理"，而是"拿当前需要的东西，去一堆信息里按相关性取用"。用最粗的话说就是：

$$\text{输出} = \text{按相关性加权求和（一堆信息）}$$

它同时解决了两件事：

1. **任意两个位置直接相连**。第 1 个词和第 100 个词之间不需要经过 99 次传递，一步就能建立联系，长程依赖不再是硬伤。
2. **可以并行**。整段序列一次性做矩阵乘法，GPU 最擅长这个；RNN 那种"必须等上一步"的串行结构被去掉了。

再加上它足够通用——文本是序列，把图片切成小块（patch）排成一队也是序列，语音也是序列——于是一套结构能到处用。**它不是"更聪明的模型"，而是"更会利用硬件、且足够通用的模型"**，这一点比数学细节重要得多。

### 4. 训练范式的变化

模型结构只是故事的一半，另一半是"怎么拿到能用的模型"：

- **预训练 + 微调**：先在海量无标签数据上练一个通用底座，再在你的小任务上小步调整。
- **自监督学习**：标签是自己从数据里造出来的（比如遮住一句话里的某个词，让模型猜）。这是"海量数据"能被用起来的关键。
- **指令微调与对齐**：让模型从"会续写文本"变成"会按你的要求做事"，再让它符合人类的偏好和安全要求。

这三样今天几乎决定了一个模型好不好用，但在 `pdl` 的尺度上都不需要实现——知道它们是干什么的即可。

## 落到代码

**先明确一件事：这一节不需要你动任何代码。** 这里只说明 `pdl` 现有的目录布局为什么能接住这些方向。

### 已有的位置，未来往上加什么

| 子包 | 未来可能新增 | 依赖它现有的什么能力 |
|------|--------------|----------------------|
| `nn/` | `conv.py`（`Conv2d`）、`pool.py`、`rnn.py`（`RNN` / `LSTM` / `GRU`）、`attention.py`、`block.py` | 现在的 `Linear` / `Sequential` / 参数管理机制 |
| `data/` | 序列 batch 的 padding 与 mask、图像增广、更大的数据集读取 | `Dataset` / `DataLoader` 的接口 |
| `trainer/` | 混合精度、学习率调度、checkpoint 与断点续训（梯度裁剪已经在 `optim/clip.py`，见第 09 章） | 现在的训练循环与日志 |
| `utils/` | 实验配置、结果记录、可视化 | `seed_everything` 与配置工具 |

> 表里**没有**"张量"和"自动微分"。这两样由 torch 提供，`src/pdl/` 里**永远不会有** `tensor/` 或 `autograd/` 子包——
> 这是本项目的"从零边界"决定的，见 `docs/roadmap.md` 第 4 节。以后加卷积时，张量能力直接用 torch 的。

### 三个具体的技术前提（未来写卷积时要先解决）

1. **张量侧基本够用，不用你扩展。** 卷积最朴素的写法（im2col）就是把每个感受野拉成一列、再调用 `matmul`；`Tensor.unfold` 能直接做窗口切片，边界补零用 `torch.zeros` + 切片赋值几行就够（注意 `torch.nn.functional.pad` 在本项目里是禁用的）。所以卷积**不需要新的自动微分**，你只需要把 `Conv2d` 写成一个新的 `Module`——这也是它比看起来好实现的原因。
2. **计算图会变得更长。** CNN 一层可能有几十个算子、RNN 展开后可能有几百步。autograd 是 torch 的、不用你改，但 Python 层的循环开销和显存会第一次真正成为瓶颈。
3. **`data/` 要处理不等长**。序列 batch 需要 padding 和 mask，而 mask 必须一路传到 loss，否则填充的 0 会被当成真实数据参与损失。这是个很容易踩的坑，等你真做的时候会单独有一个 Issue。

## 工程视角

`pdl` 的目标是"让你看懂机制"，不是"能用"。这两者之间的距离，值得你现在就有个数：

1. **性能不是一个数量级，是几个数量级。** `pdl` 的上层是**手写的 Python 循环 + PyTorch 算子**，没有算子融合、没有 `torch.compile`、没有 CUDA kernel、没有异步数据加载；每一步都有一堆 Python 开销。真实训练靠的正是这些。你的库在 Fashion-MNIST 上跑得动，不代表这个思路能上 ImageNet。
2. **可复现性在真实项目里是个流程问题，不只是 `seed_everything()`。** 除了种子，还要锁数据版本、锁依赖版本、记录超参和代码 commit。而多卡并行下浮点求和的顺序会变，**bitwise 一致本身就不保证**，只能追求"统计上一致"。
3. **测试策略要分层。** `pdl` 现在靠"**和 torch 官方实现对照**（Stage 7）+ 数值梯度校验（Stage 1）"，这套在教学库里够用。真实框架还要有：形状/dtype 的契约测试、极端数值的稳定性测试、性能回归测试，以及"CPU 和加速器结果一致"的跨后端测试。Stage 1 的梯度校验仍然是这套体系里最底层的那一环。
4. **依赖管理会变成一门手艺。** `pdl` 的依赖是"torch + numpy"，已经是相当奢侈的起点；真实项目要面对几十个包、版本冲突、需要编译的扩展，以及把环境在 CI 里原样重建出来。
5. **部署是另一条完全独立的路。** 训练出一个 `state_dict` 式的参数字典，和在手机上 100ms 内跑完一次推理，中间隔着模型导出、量化/剪枝、跨语言运行时，以及与训练解耦的版本管理。教学库里"模型 = 一个参数字典"这个假设，到这一步就不再成立了。

## 常见误解

| 误解 | 实际 |
|------|------|
| "Transformer 一定比 CNN 好" | 它们假设的结构不同。数据少、图像局部性强、算力有限时，CNN 的归纳偏置是优势而不是包袱；"更大更通用"要拿数据和算力去换 |
| "有了大模型就不需要学基础了" | 大模型就是把 MLP、反向传播、损失函数、优化器堆到极大。这些概念不懂，你只能调 API，出了问题无从下手，也无法判断别人说的对不对 |
| "预训练就是下载权重" | 下载权重只是**使用**预训练的结果。预训练本身是设计自监督目标 + 在巨量数据上做优化，那是另一个量级的工作 |
| "读完 D2L 就等于会做深度学习" | D2L 给你机制和直觉，工程能力（数据、评测、调试、复现、协作）得靠真实项目练。你在这个仓库里练的 PR / 测试 / CI，恰恰是 D2L 教不了的那部分 |
