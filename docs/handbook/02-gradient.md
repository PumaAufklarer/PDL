## 为什么需要它

假设你有一个参数 `w`，还有一个衡量"当前表现有多差"的数字 `loss`。你想让 `loss` 变小，但你不知道该把 `w` 调大还是调小。

最笨的办法：把 `w` 加一点点，看 `loss` 是变大还是变小。

```python
loss_now = f(w)
if f(w + 0.001) < loss_now:
    w += 0.001
else:
    w -= 0.001
```

**这个办法能用**，而且思路完全正确。但它有两个致命问题：

1. 有一百万个参数时，要跑一百万次 `f`——太慢
2. `0.001` 这个步长很难选：太小会被浮点误差淹没，太大就不准

**导数就是这两件事的解药**：它一次告诉你"此刻该往哪边、动多少"，而且不需要真的去试。深度学习能跑起来，全靠这个。

## 直觉：下山

把 `loss` 想象成一座山的高度，参数是你站的位置。你要走到山谷（`loss` 最小）。

- **导数** = 你脚下这个点的坡度
- **梯度** = 有很多个参数时，最陡的那个上坡方向
- **训练** = 每次朝梯度的**反方向**挪一小步

关键在这里：**你不需要知道整座山长什么样。** 你只要知道脚下这一点朝哪边是下坡，走一步，再问一次。

这就是为什么深度学习能 work——我们从不真正理解那个函数，我们只是一直往下走。

还有第二层直觉，它才是"自动微分"值钱的地方：

**数值梯度像蒙着眼睛伸脚试**——试一次只知道一个方向，试完一万个方向天就黑了。
**自动微分像手里捏着等高线图**——一次反向，所有参数的坡度同时到手，而且不管有一万个参数还是十亿个，代价都差不多。

## 最小数学

> 看不懂就跳过，先去做「落到代码」，回来再读。

### 1. 导数：`x` 动一点点，`f` 动多少

严格定义是 $f'(x) = \lim_{h \to 0} \frac{f(x+h) - f(x)}{h}$。但工程上我们不求极限，直接取一个很小的 `h`：

$$f'(x) \approx \frac{f(x+h) - f(x-h)}{2h}$$

这叫**中心差分**。注意分子是 `x+h` 减 `x-h`（跨了 `2h`），所以分母是 `2h`。它比"向前差分"准得多，误差是 $O(h^2)$ 而不是 $O(h)$。

**现在手算一遍**（这是本章最重要的一个练习，拿笔）：

$f(x) = x^2$，在 $x = 3$ 处，取 $h = 10^{-4}$：

$$f'(3) \approx \frac{(3.0001)^2 - (2.9999)^2}{2 \times 10^{-4}} = \frac{9.00060001 - 8.99940001}{0.0002} = \frac{0.0012}{0.0002} = 6$$

解析答案是 $2x = 6$。**对上了。** 你刚刚亲手用"推一下、看动了多少"算出了一个导数——这就是整门课所有梯度的原始形态。

> 顺手试试：把 `h` 换成 `1e-2`、`1e-6`、`1e-10` 各算一遍，看哪个最接近 6。
> 这是你第一次亲眼看到"精度"是个能量出来的东西，也是第 03 章为什么要挑 `h` 的伏笔。

### 2. 偏导与梯度

一个函数有多个输入时，对某一个输入求导、把其他输入当常数，就是**偏导** $\frac{\partial f}{\partial x_i}$。

把所有偏导排成一个向量，就是**梯度**：

$$\nabla f = \left(\frac{\partial f}{\partial x_1}, \frac{\partial f}{\partial x_2}, \dots\right)$$

**梯度的方向是函数上升最快的方向**，所以下降最快的方向是 $-\nabla f$——这就是 `w -= lr * w.grad` 里那个减号的来历。

记住一条约定，它会在后面每一章出现：

> **任何一个张量的梯度，形状一定和它自己完全一样。**
> `W` 是 `(3, 5)`，那 `W.grad` 就是 `(3, 5)`；`b` 是 `(5,)`，那 `b.grad` 就是 `(5,)`。
> 梯度不是一个数，是"每个参数该往哪动、动多少"的完整说明书。

### 3. 链式法则（全章最重要的一条）

复合函数 $y = f(g(x))$：

$$\frac{dy}{dx} = \frac{dy}{dg} \cdot \frac{dg}{dx}$$

用人话说：**变化沿着链条一段段传下去，每段的"放大倍数"相乘。**

**手算一遍**：$y = (3x + 1)^2$，求 $x = 1$ 处的导数。把它拆成两段——外层 $(\cdot)^2$，内层 $3x+1$：

$$\frac{dy}{dx} = \underbrace{2(3x+1)}_{\text{外层的导数}} \cdot \underbrace{3}_{\text{内层的导数}} = 2 \times 4 \times 3 = 24$$

多数层也一样，只是链更长：

$$\frac{dy}{dx} = \frac{dy}{df_n} \cdot \frac{df_n}{df_{n-1}} \cdots \frac{df_1}{dx}$$

**反向传播就是"从右往左乘这条链"。** 你在第 08 章手推一整层反向时，做的就是这件事——只不过每一段换成了矩阵。

## 落到代码

这一章**不写实现**。下面六个接口是 PyTorch 给的，用法要背下来——后面每一章都在用它们。

| 接口 | 干什么 | 容易踩的坑 |
|------|--------|-----------|
| `torch.randn(2, 3, requires_grad=True)` | 标记"这个张量要算梯度" | 只有浮点张量能要求梯度，整数张量直接报错 |
| `loss.backward()` | 从标量出发，把梯度填进所有叶子的 `.grad` | 只能对标量调用；它是**累加**不是覆盖 |
| `t.grad` | 梯度存这里，形状和 `t` 一致 | 没进计算图、或没要求梯度的张量，它是 `None` |
| `t.grad.zero_()` | 手动清空，挡住累加 | 顺序写错不报错，只出错 |
| `with torch.no_grad():` | 里面的运算不进计算图 | 第 03 章的数值侧必须包上 |
| `t.detach()` | 取值相同但断开图 | 拷数值用它，**别用 `.data`** |

**把刚才的手算和 torch 对一遍**（这是本章的验收动作，去 REPL 里跑）：

```python
import torch

x = torch.tensor(3.0, requires_grad=True)
y = x ** 2
y.backward()
print(x.grad)        # tensor(6.)  ← 和你手算的一样

a = torch.tensor(1.0, requires_grad=True)
b = (3 * a + 1) ** 2
b.backward()
print(a.grad)        # tensor(24.) ← 也是你手算的
```

**如果你手算的数和 torch 打出来的不一样，先别往下走。** 回去看「最小数学」第 3 节——那个 24 是怎么来的。

## 工程视角

### 1. `loss` 必须是标量

`backward()` 只能对标量调用。因为向量对向量的导数是**雅可比矩阵**，形状直接爆成 `N × M`，再往上还有更高阶的张量——算得出，但没人想知道。

训练里我们只关心"这批数据总体有多差"，所以 `loss` 天然是标量。手上是向量又想反向，先 `.sum()` 或 `.mean()`。但这两者不一样：`.sum()` 是各分量等权相加，`.mean()` 还额外除了元素个数。**选哪个直接改变梯度的量级，等效于改了学习率**——Stage 2 的 MSE 要不要带 `1/2` 系数就是从这里来的。

### 2. 梯度是**累加**的

`backward()` 把算出来的梯度**加到** `.grad` 上，不是覆盖。这是设计不是 bug：它让你可以攒几个 batch 再更新一次（梯度累积），显存不够时很常用。

坏处是：忘了清零，梯度一批一批滚起来，loss 直接发散。正确顺序：

```
zero_grad()       # 1. 清掉上一批的残留
forward()         # 2. 重新建图、算 loss
loss.backward()   # 3. 反向，梯度累加进 .grad
step()            # 4. 用梯度更新参数
```

**这个顺序背下来。** 它错了不会报错，只会让你 debug 到半夜：先 `step()` 再 `backward()`，等于用上一批的梯度更新这一批的参数，loss 会莫名地抖。

### 3. `.data` 和 in-place：autograd 最容易被静默破坏的地方

- 要取数值用 `t.detach()`，**别用 `t.data`**。`.data` 绕过 autograd 的版本计数，改完之后你手上是个"数值变了但计算图不知道"的张量，梯度从此悄悄错掉，还不报错。
- 对**需要梯度的叶子张量**做 in-place 运算（`x += 1`、`x[0] = 0`、`x.zero_()`），autograd 会直接报 "a leaf Variable that requires grad is being used in an in-place operation"。**报错是好事**，说明护栏还在。
- 想原地清梯度就写 `x.grad.zero_()`——in-place 的是 `grad`，不是 `x`。**参数更新是这个规则唯一的例外**：那时你本来就该在 `with torch.no_grad():` 里做，第 05 章会看到。

## 常见误解

| 误解 | 实际 |
|------|------|
| "梯度就是下降方向" | 梯度是**上升**最快的方向，我们要走 $-\nabla f$，所以代码里是 `w -= lr * w.grad` |
| "反向传播是一种优化算法" | 它是**求梯度**的方法；"怎么用梯度"是另一件事，那是优化器（第 05 章）的活 |
| "自动微分是数值近似" | 不是。它按链式法则精确地算，只是最后落在浮点数上；数值梯度才是近似 |
| "`backward()` 会自动清空上次的梯度" | 不会。它**累加**，忘了 `zero_grad()` 梯度就越滚越大，loss 会发散 |
| "梯度是个数" | 每个张量都有自己的梯度，形状和它自己一样。说"梯度"时永远要问"谁的梯度" |
| "导数和梯度是一回事" | 单变量时是；多变量时梯度是一个向量，每个分量是那一维的偏导 |
