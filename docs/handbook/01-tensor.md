# 01 · 张量：数据怎么摆

> **一句话**：张量就是"带形状的多维数组"；深度学习里所有计算都是**整批**做的，所以数据必须先摆成正确的形状——这一章的目标不是"学会建张量"，而是**让形状不出错**。
>
> **对应 D2L**：2.1 数据操作、2.2 数据预处理、2.3 线性代数 ｜ **对应 Stage**：1 ｜ **对应代码**：`src/pdl/utils/`
>
> 这是全书的地基。后面每一章的 bug，一半以上最后都会追到"形状不对"上。

---

## 为什么需要它

**先把一件容易误会的事说清楚：张量是借来的，不是你实现的。** 这一章用的是 **PyTorch 的 `Tensor`**，`src/pdl/` 里不会有张量子包，也看不到自动微分的实现——子包只有 `utils` / `data` / `loss` / `optim` / `trainer` / `metrics` / `nn`。这不是漏讲，是 [roadmap 第 4 节](../roadmap.md) 把线画在了那里：**张量加法、广播、矩阵乘不是这门课要理解的东西，层、损失、优化器、数据管道才是。** 张量不用你搭，模型和训练得你自己搭。

**但"会用"和"用对"是两件事。** 一行 `X * 2` 谁都会写，可 `(256, 784)` 和 `(784, 256)` 存的是同一批数字，意思完全不同：前者是"256 个样本、每个 784 维特征"，后者是"784 个样本、每个 256 维"。**算错了不报错，只会悄悄给你一个垃圾结果**——这是深度学习里最难查的一类 bug，它连异常都不抛。

所以本章的要求只有一条：**给你任意一行张量代码，你能在纸上把每个中间结果的形状写出来。** 这一条做到了，第 02 章的梯度、后面的线性层都会顺很多。

## 直觉：一摞 Excel 表

把张量想成一摞 Excel 表：

| 维数 | 形状 | 像什么 |
|------|------|--------|
| 0 维 | `()` | 一个格子 |
| 1 维 | `(784,)` | 一行 |
| 2 维 | `(256, 784)` | 一张表：256 行 × 784 列 |
| 3 维 | `(256, 28, 28)` | 一叠 256 张 28×28 的小表 |
| 4 维 | `(256, 3, 28, 28)` | 256 叠，每叠 3 张彩色通道表 |

- **形状** = 每层有多少格，所有维度相乘 = 一共多少个数字；**第 0 维是批次** = 每次搬一摞表，不是一张一张搬。`X[0]` 就是"这个 batch 里的第 0 个样本"。
- **广播** = 小表格和大表格逐格运算时自动"复印"到一样大——**但不是真的复印**。
- **矩阵乘** = 把一张表的行，和另一张表的列逐个"配对加权求和"。
- **`reshape`** = 同一摞表按新行列数重新念一遍，格子里的数字一个没动；**`transpose`** = 真的把行和列对调了。

**看张量先看 shape，再看里面是什么数。** 反过来的人一定会踩坑。

## 最小数学

> 看不懂就跳过，先去做「落到代码」，回来再读。

### 1. 形状就是"每维多长"

$$\text{numel} = \prod_{i} \text{shape}[i]$$

```python
x = torch.randn(256, 3, 28, 28)
x.shape      # torch.Size([256, 3, 28, 28])：shape 就是这个元组
x.numel()    # 602112 = 256*3*28*28，就是上面的连乘
```

### 2. 广播：右对齐，长度 1 或缺失的能被拉伸

从最右开始逐位对齐，每一位要么两边相等、要么其中一边是 $1$、要么短的那边**不存在**（左边补 $1$）；满足就取较大值，不满足就报错。偏置加到每一行，就是这条规则在干活：

```python
# 右对齐：  (256, 3, 28, 28)
#                 (1, 28,  1)   ← 左边补 1 → (1,1,28,1) → 逐位取 max → (256,3,28,28)
X = torch.randn(256, 784)
b = torch.randn(784)          # 只有 784 个数
(X + b).shape                 # (256, 784)：b 被"复印"到 256 行上
```

### 3. 矩阵乘：一个公式，三种看法

$$c_{ij} = \sum_{k} a_{ik} b_{kj}, \qquad (m, k) \otimes (k, n) \to (m, n), \qquad (B, m, k) \otimes (k, n) \to (B, m, n)$$

中间的 $k$ 必须相等，结果里它被"消掉"。批量版本只动最后两维，前面的维度一起广播——**这就是"第 0 维是批次"的数学表达**。

```python
X, W = torch.randn(256, 784), torch.randn(784, 10)
Y = X @ W                  # (256, 10)
Y[3, 5]                    # 行内积：X 的第 3 行 · W 的第 5 列 = (X[3] * W[:, 5]).sum()
Y[:, 5]                    # 列的线性组合：把 X 的各列按 W[:, 5] 当权重加起来
(torch.randn(8, 256, 784) @ W).shape   # (8, 256, 10)：W 被 8 个 batch 共用
```

`view` 和 `reshape` 的区别一句话：**`view` 要求内存连续，不连续就直接报错；`reshape` 会在必要时替你拷贝一份。** 默认用 `reshape`。

## 落到代码

这一章**没有要实现的东西**——张量不是我们写的。Stage 1 在代码上的任务是：把下面这些操作练到不用查文档，再用它们写出 `src/pdl/utils/` 里的数值梯度校验器。

### Stage 1 必须掌握的 torch 操作

| 类别 | API | 典型用途 | 易错点 |
|------|-----|----------|--------|
| 创建 | `torch.tensor` / `zeros` / `ones` / `randn` / `arange` | 造数据、造参数、造索引 | 从 `list` 造出来是 `int64`，要显式 `dtype=torch.float32` |
| 查看 | `.shape` / `.ndim` / `.numel()` / `.dtype` / `.device` | 写断言、定位 bug 的第一眼 | `len(t)` 只给第 0 维长度，元素总数要 `numel()` |
| 变形 | `reshape` / `flatten` / `squeeze` / `unsqueeze` | 图片摊平成向量；给广播补一个长度 1 的维 | `reshape(-1, D)` 里只允许一个 `-1`；`squeeze()` 不传参会把所有 1 都删掉 |
| 换轴 | `transpose(d0, d1)` / `permute(...)` / `.T` | 转置权重、`(N,H,W,C)` 与 `(N,C,H,W)` 互转 | 换轴后内存不连续，后面接 `view` 会报错 |
| 逐元素 | `+ - * /`、`**`、`exp` / `log`、`sqrt`、`clamp` | 损失、激活、数值稳定（第 07 章 softmax 的重头戏） | `*` 是逐元素乘，不是矩阵乘 |
| 归约 | `sum` / `mean` / `max`、`dim=`、`keepdim=True` | 把一批损失压成一个数；按 batch 维求和 | `keepdim=True` 才能保住那一位继续广播；本课程统一写 `dim=` |
| 矩阵乘 | `@` / `torch.matmul` | `X @ W`、批量矩阵乘 | 一维张量参与会**掉一个维**；两边 dtype 必须一致 |
| 索引 | `x[i]`、`x[:, 0]`、布尔掩码 | 取一个样本、按标签取分数 | 用张量当索引时它必须是 `int64` |
| dtype / device | `.to(dtype=..., device=...)` / `x.new_zeros(...)` | 保证所有张量同精度、同设备 | 每次 `.to()` 都可能是真拷贝，别写在循环里 |

### 形状速查

| 形状 | 是什么 | 谁产生它 |
|------|--------|----------|
| `(N, D)` | N 个样本，每个 D 维特征 | `DataLoader` 吐出的一个 batch |
| `(N,)` | N 个标签 | 标签张量（`int64`） |
| `(N, C)` | N 个样本在 C 个类别上的分数（logits） | `Linear` 的输出 |
| `(N, C, H, W)` | N 张 C 通道、H×W 的图 | 图像数据；`(N, H, W, C)` 是它的"轴换了"版本 |
| `(in, out)` | 线性层的权重 `W` | `pdl.nn.Linear`（Stage 5） |
| `(N, in) @ (in, out) → (N, out)` | 一层线性变换 | 全课程出现最多的一行 |

**形状对不上时，按这个顺序排查：**

1. **别猜，先打印。** 出错那一步的两个输入各自是什么形状？只看报错里提到的结果没用。
2. **右对齐逐位比**：相等 / 有一个是 1 / 缺维 → 能广播；否则就是真的不匹配。
3. **是矩阵乘吗**：只看最后两维，`k` 必须相等；前面的维度按广播规则处理。
4. **是不是把 batch 维弄丢了？** 最常见的是 `(N, D)` 和 `(D, N)` 混了，或者一维 `@` 掉了维。
5. **把你手推的形状写成断言**（见「工程视角」第 1 条），跑一遍验证——不要在脑子里过。

几行用来对答案的示意（不是要实现什么）：

```python
X, W, b = torch.randn(256, 784), torch.randn(784, 10), torch.randn(10)
(X @ W + b).shape                              # (256, 10)：广播把 b 送到每一行
X.reshape(256, 28, 28).shape                   # (256, 28, 28)：只换读法
X.reshape(256, 28, 28).transpose(1, 2).shape   # (256, 28, 28)：真的换了轴
torch.randn(784) @ W                           # (10,)：一维进来，就掉一维出去
```

## 工程视角

这一章的考点不在"会不会算"，而在**你怎么保证自己摆对了、怎么让别人看得出你摆对了**。

### 1. 形状断言写成 `assert`，不要写成注释

```python
def forward(self, x: Tensor) -> Tensor:
    assert x.ndim == 2, f"期望 (N, in)，收到 {tuple(x.shape)}"
    assert x.shape[-1] == self.in_features, f"最后一维应是 {self.in_features}"
```

注释会过期，断言不会：**第一现场炸掉**（而不是三层之后报一个看不懂的错）、**报错里带真实形状**（省一次 print 调试）、**当接口文档读**。如果你介意 `python -O` 会去掉断言，就改写成 `if ...: raise ValueError(...)`；本项目测试永远带断言跑，`assert` 够用。

### 2. dtype：全课程统一 `torch.float32`，标签用 `torch.int64`

- **torch 的默认不是 numpy 的默认。** `torch.tensor([1.0]).dtype` 和 `torch.randn(2).dtype` 都是 `float32`，numpy 默认却是 `float64`。从 numpy 转过来**必须显式给**：`torch.tensor(arr, dtype=torch.float32)`。
- **为什么不用 `float64`**：省一半内存和带宽，和 torch 默认行为一致，真实训练本来也用 `float32`。代价要认：float32 只有约 7 位有效十进制，**数值梯度校验的阈值要放到 `1e-4` 量级**，别照抄 numpy 时代的 `1e-12`（比 float32 精度还小，必然假红）。
- **标签必须 `int64`**：`torch.tensor([1, 2]).dtype` 天然是 `int64`，但浮点标签不会自动帮你转，交叉熵和索引会直接报错，习惯上补一句 `y = y.long()`。
- **dtype 混用会出事**：`torch.randn(2, 2) @ torch.ones(2, 2, dtype=torch.int64)` 直接抛错（矩阵乘要求两边同 dtype）。统一在函数入口转一次。

### 3. device：所有张量要么显式给，要么从输入推导

```python
z = torch.zeros(D, device=x.device, dtype=x.dtype)   # 照着输入来；等价写法 z = x.new_zeros(D)
```

**禁止硬编码 `device="cpu"` 或 `device="cuda"`。** CPU 张量和 GPU 张量不能直接运算，报错信息还常常指向别处。CI 上没有 GPU，所以"在 CPU 上也能跑"是硬约束——Stage 6 专门讲这件事。

### 4. 测相等用 `torch.testing.assert_close`，不要自己写 allclose

它默认还会检查 `dtype`、`device`、`shape`；而默认容差是**按 dtype 定**的（见 [官方文档](https://docs.pytorch.org/docs/stable/testing.html)）：

| dtype | 默认 `rtol` | 默认 `atol` |
|-------|------------|------------|
| `float32` | `1.3e-6` | `1e-5` |
| `float64` | `1e-7` | `1e-7` |

所以梯度校验里**显式写出容差**，别依赖默认值——默认值是给普通数值比较的。

而且**梯度校验本身要在 `float64` 下做**（第 03 章会讲为什么，以及怎么把张量提到 `float64`）：

```python
torch.testing.assert_close(grad_auto, grad_num, rtol=1e-6, atol=1e-8)   # float64 下
```

如果你偷懒留在 `float32`，容差就得放宽到 `1e-3` 量级。那不是"校验标准变松了"，而是 `float32` 只有约 7 位有效数字，`1e-5` 量级的差分本来就被舍入误差淹没了。**放宽容差是在掩盖精度不足，不是在解决问题。**

### 5. 三个危险操作

| 危险操作 | 会发生什么 | 怎么办 |
|----------|-----------|--------|
| `.data` | 给你一个绕过 autograd 的张量，**看着能用、梯度悄悄是错的**，还不报错 | 本仓库**禁止使用**；要断梯度用 `detach()` |
| in-place：`x += 1`、`relu_()` | 反向要用前向的值，你原地覆盖了它，计算图就坏了；报错常提 "a leaf Variable that requires grad is being used in an in-place operation" | 写成 `x = x + 1`；唯一例外是参数更新，那本来就该在 `with torch.no_grad():` 里做 |
| `transpose` 后接 `view` | 报 "view size is not compatible with input tensor's size and stride" | 用 `reshape`（必要时自动拷贝），或先 `.contiguous()` |

## 常见误解

| 误解 | 实际 |
|------|------|
| `reshape` 和 `transpose` 差不多 | `reshape` **不重排元素**，只换一种读法，内存里的顺序一个没变；`transpose` 换的是轴顺序，读出来的位置真的变了 |
| 广播会先把它复制成大张量 | 不复制**输入**（`expand` 出来的张量 strides 里有 0，假装那边有一份）；但**输出是真的占内存**：`(10000,1) + (1,10000)` 结果就是 1 亿个数 |
| `a * b` 就是矩阵乘 | `*` 是**逐元素**乘（还要广播）；矩阵乘是 `@` / `matmul` |
| 一维张量可以直接和矩阵乘，结果还是二维 | `(k,) @ (k, n) → (n,)`，**结果会掉一个维度**；要 `(1,k) @ (k,n)` 才是 `(1,n)`。训练代码里永远别让 batch 维消失 |
| `torch.tensor([1.0])` 是 `float64` | torch 默认 `float32`，`float64` 是 numpy 的默认。从 numpy 转过来必须显式给 dtype |
| `view` 和 `reshape` 完全等价 | `view` 只在内存连续时能用，转置或切片之后就会报错；`reshape` 必要时拷一份，代价是它可能不再和原张量共享内存，所以本项目统一用 `reshape` |
