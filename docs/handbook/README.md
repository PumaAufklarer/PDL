# PDL Handbook · 知识点手册

这是一本**为了让你能动手写代码而写的手册**，不是教材的替代品。

D2L 讲得比你需要的更全；这份手册只回答一个问题：**这个知识点，在你写 `pdl` 的时候，到底对应到哪一行代码。**

---

## 怎么读

每章结构固定：

| 小节 | 作用 |
|------|------|
| **一句话** | 阻塞式结论。读完这句就该知道这章要干什么 |
| **为什么需要它** | 从问题出发，而不是从定义出发 |
| **直觉** | 生活化的类比，没有公式 |
| **最小数学** | 只保留能落到代码的公式。**看不懂可以先跳过** |
| **落到代码** | 对应 `pdl` 的哪个模块、接口长什么样。**只给接口，不给实现** |
| **工程视角** | 怎么写测试、边界在哪、数值上有什么坑 |
| **常见误解** | 新手最容易想歪的地方 |
| **自测题** | 答不上来就说明还没到可以写代码的程度 |

---

## 数学基础不好的话，按这个顺序读

**默认顺序**是 `直觉 → 最小数学 → 落到代码`。但如果你看到公式就头疼，用下面这个顺序：

```
直觉  →  落到代码  →  （写完代码再回来）最小数学
```

具体怎么做：

1. 读「直觉」，知道这东西在干嘛。
2. **直接跳到「落到代码」**，看接口和数据结构，动手写。
3. 写到卡住（比如不知道该乘还是该转置），再翻回「最小数学」，**只看你卡住的那一条公式**。
4. 代码跑通、测试变绿之后，再回头把「最小数学」完整读一遍。这时候公式有锚点了，会顺很多。

这不是偷懒，这是正常的学习顺序。**先有例子，再有符号**——反过来对大多数人都不成立。

### 三条提醒

- **不要提前补数学。** 需要哪个概念，就查哪一个。`docs/roadmap.md` 第 3 节列了这门课需要的**全部**数学，一共 12 条，没有更多。
- **允许反复横跳。** 同一节读三遍是正常的。
- **不要背公式。** 每一章的最后都有一个能跑的检查：公式记错了，测试会红。让测试替你记。

## 和 D2L 的关系

- D2L 是**教材**：知识完整、推导严谨、例子丰富。适合当参考书查。
- 这份手册是**施工图**：告诉你现在这一步在整体里的位置，以及代码上要注意什么。
- `docs/roadmap.md` 是**施工计划**：决定先做哪一步，以及每个 Issue 叫什么名字。

推荐顺序：**读手册对应章节 → 读 D2L 对应章节 → 写代码 → 卡住了回来查手册 → 提 PR。**

**不要试图先把 D2L 读完再动手。** 那本书 700 多页，读完你就放弃了。
