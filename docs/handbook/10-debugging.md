# 09 · 训练调试手册

> **一句话**：模型不收敛时，**先怀疑自己的代码，再怀疑超参数，最后才怀疑数学**；绝大多数"模型不行"其实是 shape 错了、忘了 `zero_grad()`、忘了切 `train()/eval()`。

---

## 为什么需要它

普通代码坏了会报错；训练坏了**不报错**。loss 还是浮点数，程序照跑，只是数字偷偷不降。

这叫**静默错误**：没有异常可看，唯一的线索是那条 loss 曲线和几个你自己打印出来的数字。所以调试能力本质上就是**观测能力**——线索得你自己造。好消息是问题的形状非常固定，同一套顺序能解决九成以上的"不收敛"。

---

## 直觉

做了道菜，难吃。正常人先想自己是不是忘放盐、把糖当盐了（**自己的操作**）；再想火大火小（**参数**）；最后才怀疑菜谱本身写错了（**理论**）。没人一上来就怀疑热力学第二定律。训练也是一样：

- 忘放盐 = 标签和输入错位、忘了 `zero_grad()`、模型还停在 `eval()` 模式
- 火候 = 学习率、batch size、正则强度
- 菜谱错 = 损失函数推错了、反向公式错了

**顺序反了，你会花一整天推导交叉熵，最后发现是标签错位。** 医生也一样：先量体温、问病史（便宜检查），再上 CT（贵检查），不会一上来就开颅。

## 最小原理

> 这节没有公式推导，只有两个"为什么"。

### 1. 为什么必须"先怀疑代码，再怀疑数学"

不是态度问题，是概率和成本问题。**概率上**，bug 的分布极不均匀：shape 错位、忘了 `zero_grad()`、忘了切模式占了绝大多数，而且都是**确定性**的——同一份数据跑两次，坏法完全一样；反过来，"数学抄错了、而且梯度校验还没抓住"的概率低得多。

**成本上**，查一个 shape 是 30 秒，检查一遍反向推导是半天。所以流程固定为：**代码 → 数据 → 超参数 → 数学**，前三个都排除了，再动第四个。

### 2. loss 曲线的形状携带什么信息

训练时你能观测的只有一个标量序列，它的形状至少含三样东西：

- **斜率** = 在降还是在平。平说明梯度接近 0，或者参数压根没更新。
- **抖动幅度** = 步长和学习率的关系。一步是 $w \leftarrow w - \eta \nabla L$，$\eta$ 太大会跨过谷底再跨回来，曲线上就是震荡。
- **两条线的间距**（train vs val）= 泛化信息，也是唯一能告诉你过拟合的信号。

### 3. loss 曲线模式识别表（最该背下来的东西）

| 症状 | 可能原因 | 下一步动作 |
|------|----------|------------|
| 完全不变，一条平直线 | 梯度为 0 或参数没更新：参数没挂 `requires_grad`、学习率为 0、loss 没接进计算图、数据与标签错位到学不到东西 | 先打 `grad_norm()`；是 0 就查 `requires_grad` 和计算图；再跑小批次过拟合 |
| 缓慢下降，慢得离谱 | 学习率太小；初始化尺度不对；输入没归一化；梯度小到被浮点吃掉 | 按量级扫学习率；看每层激活的均值/方差 |
| 剧烈震荡，上下乱跳 | 学习率太大；batch 太小导致梯度噪声大；数据没打乱，一个 batch 全是同类 | 学习率降一个量级；开 shuffle；加大 batch |
| 先降后升 | 过拟合（train 继续降、val 开始升）；或后期 lr 过大跳出最优点 | 看 val 曲线区分是哪一种；加正则/早停，或加 lr 衰减 |
| 变成 nan / inf | 数值溢出：`exp` 没保护、`log(0)`、除 0、lr 爆炸、梯度爆炸 | 先降 lr；加梯度裁剪；定位**第一个**变 nan 的算子和它的输入 |
| train 降，val 升 | 典型过拟合 | 加数据/权重衰减/Dropout/早停。说明模型确实在学，是好消息 |
| 两条都高且很接近 | 欠拟合：容量不够或训练不够 | 加大模型、训练更久、检查特征本身有没有信息 |
| 准确率卡在随机水平（10 分类卡 10%） | 通常是数据问题：标签错位、类别全标成同一个；或验证时没切 `eval()` | 打混淆矩阵；可视化几个样本和标签；跑小批次过拟合 |

### 4. 该打印什么

除了 loss，还有四个数字能极大缩短排查时间。学习率也要打，用了 scheduler 之后尤其如此——曲线难看时先确认 lr 没被意外改成 0：

- **梯度范数**：为 0 → 没更新；突然到 1e6 → 要爆炸。
- **参数范数**：缓慢变化正常，突然暴涨说明发散。
- **每层激活的均值/方差**：方差逐层衰减到 1e-8 说明信号死了（梯度消失），逐层放大到 1e3 说明要溢出。**这是定位问题出在哪一层的最快手段。**
- **每个 epoch 的耗时**：和精度无关，但突然变慢说明数据加载或内存出问题了。

## 落到代码

### 五个标准动作（按顺序做，做完一个再做下一个）

**① 先在小批次上过拟合。** 拿 10 个样本，关掉正则，训几百步，看能不能把 train loss 压到接近 0。容量足够的模型记住 10 个样本是必然能做到的；做不到就说明**代码有 bug**，和"模型行不行""数据够不够"无关。

**② 检查数据。** 标签有没有和输入错位（差一位是经典 bug）；有没有 NaN；取值范围是否正常；类别是否平衡；挑 4–8 个样本连标签可视化出来看。数据问题用眼睛看，别靠推理。

**③ 做梯度校验。** 小模型、小输入，数值梯度和解析梯度比相对误差。这是第 03 章那套设施的直接复用——**写完每一层都该跑一次**。

**④ 扫学习率。** 按量级扫 `1e-1 / 1e-2 / 1e-3 / 1e-4`，各跑一两百步，曲线画在一起看，取下降最快又没震荡的那一档再细化。

**⑤ 关掉所有正则再试一遍。** `weight_decay=0`、`dropout=0`、增广全关。正则太强会让曲线看起来像"模型不行"，实际只是被压制。

### 随机种子：什么时候必须固定，什么时候必须换

**必须固定**：调试任何 bug 时。否则你改了 A、B 也变了，分不清是谁造成的。调试的前提是只有一个变量在动。**必须换**：确认修复有效之后。一个种子下调好、换个种子又坏，说明你调的是噪声不是规律，最终结论至少跑 3 个种子。节奏就是：固定种子调 bug → 换种子验证泛化 → 报告时说明用了哪几个种子。

## 工程视角

### 1. 每个调过的 bug，都变成一条回归测试（本章最值钱的一条）

你花三小时定位到一个"忘了 `zero_grad()`"，手动改掉——下次还会再犯。正确的收尾是写一个**会因为这个 bug 而失败**的测试，成本远低于第二次踩同一个坑，而且它把"经验"变成了仓库的资产：

- "标签错位" → 构造已知的 `(x, y)`，断言过完 DataLoader 配对关系没变
- "忘了零梯度" → 连续两步 `backward()`，断言梯度累加而非覆盖；再断言 `zero_grad()` 后归零
- "`eval()` 没切回来" → `eval()` 后 Dropout 输出确定，`train()` 后随机

### 2. 用 `assert` 把不变量写进代码

注释会说谎，`assert` 不会。把"你认为一定成立的事"写下来：

- **形状**：`assert x.shape == (batch, in_features)`、`assert y_hat.shape == y.shape`
- **dtype**：`assert x.dtype == torch.float32`，混进 float64 要立刻报错
- **数值**：`assert torch.isfinite(loss)`、`assert not torch.isnan(x).any()`
- **语义**：`assert (probs.sum(dim=-1) - 1).abs().max() < 1e-5`、`assert 0 <= y.max() < num_classes`。注意 `torch.allclose` 的第二个参数**必须是张量**，写 `torch.allclose(x, 1.0)` 会直接 `TypeError`

关键是**失败要早**：在算 loss 前断言，比在下游看到 NaN 再回头找快十倍。调试期把断言开满，性能敏感时再关，关之前先确认这些不变量已被测试覆盖。

### 3. 最小复现：把 100 行缩到 5 行

"我的训练脚本不收敛"不是个能排查的问题，太大了。做法是**逐层删**：删掉正则还坏吗？换成 2 层还坏吗？换成 8 个样本还坏吗？最后留下的那 5 行就是 bug 所在。一个好的最小复现满足三条：**没有随机性**、**几秒能跑完**、**删掉任何一行现象就消失**。它也正是你要贴进 Issue 的东西。

### 4. 常见错误检查清单

- [ ] 标签和输入错位（差一位、排序键用错、`X[i]` 配了 `y[i+1]`）
- [ ] 忘了 `optimizer.zero_grad()`（梯度累加，等效学习率逐 step 变大）
- [ ] 忘了 `train()` / `eval()` 切换（验证时 Dropout 还在丢、BatchNorm 还在更新统计量）
- [ ] shape 被隐式广播掩盖（`(N,1)` 减 `(N,)` 得到 `(N,N)`，不报错但全错）
- [ ] float32 / float64 混用（和 torch 默认 dtype 不一致，或中途被 upcast）
- [ ] 数据没打乱（连续同类样本让梯度方向反复横跳）
- [ ] loss 归约方式不一致（一处 `sum` 一处 `mean`，等效学习率差 batch 倍）
- [ ] 验证时参数还在计算图里（一直建图，内存持续涨）

## 常见误解

| 误解 | 实际 |
|------|------|
| "loss 不降说明模型不行/任务做不了" | 先排除代码问题。一个能记住 10 个样本的模型在 10 个样本上都学不动，是代码不行，不是模型不行 |
| "NaN 一定是学习率太大" | 学习率只是一类原因。`log(0)`、除 0、`exp` 溢出、标签越界都会产生 NaN。先定位**第一个**出现 NaN 的算子，而不是直接调 lr |
| "训练集准确率高就说明没问题" | 训练集准高只说明有拟合能力，甚至可能说明标签泄漏了。要看 gap：train 好 val 差是过拟合，两个都好才是真的好 |
| "这次没收敛，重跑一次说不定就好了" | 不固定种子的"重跑"是在碰运气，它掩盖 bug 而不是解决 bug。随机性带来的差异是线索，不是骰子 |
