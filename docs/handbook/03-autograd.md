# 03 · 梯度校验：你怎么知道梯度是对的

> **一句话**：`backward()` 是黑盒，它算错了不会报错，只会让模型悄悄学不动。这一章你要造一把**完全独立**的尺子，用它把梯度钉死。
>
> **对应 D2L**：2.5 自动微分（工程延伸）｜ **对应 Stage**：1 ｜ **对应代码**：`src/pdl/utils/gradcheck.py`
>
> 这是本课程第一个"真正交付的工程组件"，也是后面每一层、每一个损失的标配测试。

---

## 为什么需要它

第 02 章你写下了这行代码，它给了你一个 `tensor(6.)`：

```python
x = torch.tensor(3.0, requires_grad=True)
(x ** 2).backward()
print(x.grad)
```

但你凭什么相信它？

**因为你手算过。** 你知道 $x^2$ 的导数是 $2x$，在 $x=3$ 处是 6。你是拿**另一个来源**（你脑子里的求导公式）核对过的。

现在把场景换成 `h = relu(x @ W + b)` 接上交叉熵接上十层——**没有人能手算。** 那怎么办？

这才是这一章真正的问题。它比"梯度怎么算"重要得多，原因是深度学习里的 bug 有一个特别恶劣的性质：

> **梯度错了，程序不会崩、不会报错、不会出 `nan`。它只会让模型学得慢一点、或者干脆学不动。**
> 你会以为是学习率不对、数据不行、模型太小，查一星期都查不到真正的地方。

所以必须有一套**不依赖 `backward()` 实现**的独立验证手段。它叫**数值梯度校验**——而它的核心公式，你在第 02 章已经手算过两遍了。

---

## 直觉：两把尺子

你手上有把尺子，想量一根棍子有多长。量出来 30 厘米——但你不知道尺子准不准。

怎么办？**换一把来源完全不同的尺子再量一次。** 还是 30 厘米，你就敢信了。

- **第一把尺子**：`torch.autograd`，按链式法则精确地算
- **第二把尺子**：数值梯度，它完全不看 `backward()` 的任何一行代码，只会做一件事——**把输入推一下，看输出动了多少**

这两把尺子的内部原理毫无关系，所以它们同时给出同一个答案时，你就有了真正的信心。

反过来说，如果你用"自己写的 `backward()`"去验"自己写的 `backward()`"，那不叫验证，那叫自言自语。

> **这一章所有的工程细节，都是在保证第二把尺子是真独立的、量得准的。** 下面「工程视角」那五条，本质上都是"尺子怎么造才不糊弄自己"。

## 最小数学

> 看不懂就跳过，先去做「落到代码」，回来再读。

### 中心差分（第 02 章那个式子，现在要自动化）

$$f'(x) \approx \frac{f(x+h) - f(x-h)}{2h}$$

对**张量**也成立，而且更简单：对某个元素的偏导，就是把**只有它**推一下、其他都不动。

$$\frac{\partial f}{\partial x_i} \approx \frac{f(x_1, \dots, x_i + h, \dots) - f(x_1, \dots, x_i - h, \dots)}{2h}$$

所以实现就是：**对张量的每个元素轮流推一下**。`(3, 5)` 的张量有 15 个元素，就推 30 次、算 30 次前向。慢，但它准，而且和 `backward()` 毫无关系——这正是我们要的。

### 相对误差：怎么判断"两个数一样"

拿到两把尺子的读数 $a$（autograd）和 $n$（数值），怎么判断它们一致？**不能用绝对误差。**

梯度可能是 `1e-8`（某个几乎不影响的参数），也可能是 `1e3`（某个很敏感的参数）。固定一个阈值 —— 比如 `|a - n| < 1e-6` —— 对前者太松（错得离谱也放过），对后者太严（对的也冤枉）。

用**相对误差**：

$$\text{rel\_err} = \frac{|a - n|}{\max(1,\ |a| + |n|)} < 10^{-6}$$

分母里的 `max(1, ...)` 是为了防一个具体的坑：当 $a$ 和 $n$ **都接近 0** 时，直接相除会得到一个巨大的数。举个数：$a = 0$、$n = 10^{-9}$，绝对差只有 $10^{-9}$，本来是合格的；但 $\frac{10^{-9}}{10^{-9}} = 1$，完全不除就会误报成"误差 100%"。

加上 `max(1, ...)` 之后：$\frac{10^{-9}}{\max(1,\ 10^{-9})} = 10^{-9} < 10^{-6}$，**通过**。这才是对的。

## 落到代码

```python
# src/pdl/utils/gradcheck.py

def numerical_grad(expr_fn: Callable[[], Tensor], tensor: Tensor, h: float = 1e-5) -> Tensor: ...

def check_gradient(expr_fn: Callable[[], Tensor], *tensors: Tensor,
                   h: float = 1e-5, tol: float = 1e-6) -> None: ...
```

`expr_fn` 是一个**无参闭包**——它不收任何参数，只负责"把前向再算一遍"：

```python
check_gradient(lambda: (x ** 2).sum(), x)
check_gradient(lambda: layer(x).sum(), x, layer.W, layer.b)
```

**为什么设计成无参闭包？** 因为这样能验证**任何在表达式里出现过的张量**——包括层里面的 `W`、`b`。你不需要把它们从层里抠出来当实参传，只要它们在闭包里出现过就行。第 08 章每一层的梯度测试都靠这个设计。

### 契约（动手前先读懂这五条）

- `expr_fn()` 必须返回**标量**张量，而且每次调用都重跑一遍完整前向
- `numerical_grad` 对 `tensor` 的**每个元素**做中心差分，一共会把 `expr_fn` 调用 `2 × tensor.numel()` 次；返回值形状与 `tensor` 相同
- 数值侧整段包在 `with torch.no_grad():` 里；不包的话，每扰动一个元素就多建一张计算图
- 被扰动的元素**必须还原**，否则后面所有元素都在被污染的输入上求差
- `check_gradient` 先跑一次 `expr_fn().backward()` 拿解析梯度，再对每个传入张量比相对误差；**超阈值就抛异常，并把最大相对误差打进消息里**——不然你不知道差多远

**只给契约，实现自己写。** 这是你在这个项目里第一个真正要交付的组件。

## 工程视角

这一章真正的考点不是"能不能算出梯度"，而是**你凭什么相信算出来的是对的**。

### 1. 五个决定成败的细节

- **`h` 不能太小，也不能太大。** `1e-10` 时 `f(x+h) - f(x-h)` 那点差会被浮点精度吃光，结果是 0 或纯噪声；`1e-2` 时截断误差又冒出来。`1e-5` 是好起点，试 `1e-4`、`1e-6` 看哪个更稳。
- **比相对误差，不比绝对误差。** 理由见「最小数学」。
- **数值侧必须 `torch.no_grad()`。** 否则每扰动一个元素就重建一张计算图，一千个元素就是一千张图。
- **被扰动的元素必须还原。** 加完 `h` 算完一定要写回原值；漏了这一步，后面的元素全在被污染的输入上求差，误差会大到大到你开始怀疑自己的数学。
- **校验时把 dtype 提到 `float64`。** 项目默认算 `float32`，但 `1e-5` 量级的差在 `float32` 下会被舍入误差淹没（有效位数只有 7 位左右）。**梯度校验是少数几个该显式用 `float64` 的地方**，PyTorch 官方 `gradcheck` 也强制要求 `float64`。

> 注意最后一条和"统一 float32"不冲突：**float32 是训练时的约定，float64 是校验时的工具。**
> 就好比称菜用克，标定砝码用毫克——两件事。

### 2. 测试怎么写（三层）

- **先验校验器自己**：拿已知导数对——`x**2 → 2x`、`exp → exp`、`log → 1/x`、`(x @ W).sum()` 对 `W` 是 `x.T`、对 `x` 是 `W.T`。
  **校验器也是被测对象**，它红了后面全白测，所以它是第一个要测的东西。
- **再验边界**：广播、非方阵 `W`、batch 大小为 1、单元素张量、全零输入。
- **最后验别人的实现**：第 08 章的每一层、第 04 章的 `MSELoss`、第 07 章的 `CrossEntropyLoss`，都要过一遍。

### 3. 永远不要拿自己的代码测自己

数值梯度之所以有用，**正因为它和 `backward()` 的实现毫无关系**。用两套共享假设的东西互测，等于什么都没测。

这条纪律的另一面同样重要：**测试里拿官方实现当 oracle 是允许而且鼓励的。**
项目有一条"`src/pdl/` 里禁用 `torch.nn` / `torch.optim`"的硬边界（见 `docs/roadmap.md` 第 4 节），但那条边界**只约束你要自己实现的部分，不约束你用来验证的部分**。第 07 章会拿 `torch.nn.functional.cross_entropy` 当标准答案来测你手写的交叉熵——那正是"对照"的正确用法。

## 常见误解

| 误解 | 实际 |
|------|------|
| "梯度算错了会报错" | **不会。** 这是本章存在的唯一理由。梯度错只表现为"学不动"，你会去怪数据、怪学习率、怪模型太小 |
| "用相对误差是吹毛求疵" | 梯度的量级跨越十几个数量级，绝对误差要么放过错的、要么冤枉对的 |
| "校验器是我们自己写的，那它不也是'自己的代码'吗" | 关键在**原理独立**：它不读 `.grad`，只用"推一下看输出动多少"。和 `backward()` 共享零行代码 |
| "校验太慢了，训练里也开着吧" | 校验是**开发期**的工具，测试里跑；训练时逐元素推 30 次是不可能的。它保证"写对了"，不负责"跑得快" |
| "float64 和项目统一 float32 冲突" | 不冲突。float32 是训练的约定，float64 是校验的工具。官方 `gradcheck` 也这么做 |
| "校验通过了就说明模型没问题" | 只说明**梯度算对了**。模型能不能学到东西是另一回事（见第 06 章过拟合、第 10 章调试） |
